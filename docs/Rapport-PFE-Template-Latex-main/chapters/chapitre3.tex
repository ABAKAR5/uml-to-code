\section*{Introduction}
\addcontentsline{toc}{section}{Introduction}

Dans ce troisième et dernier chapitre, nous présentons la phase de réalisation du projet UML-to-Code. Nous commençons par décrire l'environnement de développement et les outils techniques utilisés, puis nous détaillons l'implémentation du backend et du frontend. Nous présentons ensuite le déploiement de l'application, et nous terminons par les tests et les résultats obtenus.

\section{Outils Techniques Utilisés}
%=============================================================

\subsection{Outils de développement}

\subsubsection{Visual Studio Code}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/vscode.png}
    \caption{Visual Studio Code}
\end{figure}

Visual Studio Code (VS Code) est un éditeur de code source léger mais puissant, développé par Microsoft. Il a été utilisé comme environnement de développement principal pour ce projet. Il offre une grande flexibilité grâce à ses nombreuses extensions, notamment pour Python, React.js et LaTeX.

\subsubsection{StarUML}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/staruml.png}
    \caption{StarUML}
\end{figure}

StarUML\fnStarUML{} est un outil de modélisation UML professionnel. Il a été utilisé pour créer les diagrammes de classes, de cas d'utilisation et de séquence du projet. Il permet également l'export des diagrammes au format XMI, format utilisé comme entrée principale de l'application.

\subsubsection{Git \& GitHub}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/github.png}
    \caption{Git \& GitHub}
\end{figure}

Git est le système de gestion de versions utilisé pour suivre l'évolution du code source tout au long du développement. GitHub a été utilisé comme plateforme d'hébergement du dépôt distant\fnGitHub, permettant la sauvegarde du code et son partage en open source.

\subsection{Technologies Backend}

\subsubsection{Python}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/python.png}
    \caption{Python}
\end{figure}

Python est le langage de programmation utilisé pour développer le backend du projet. Sa simplicité, sa lisibilité et sa richesse en bibliothèques en font un choix idéal pour le développement web, le parsing XML et l'intégration d'API d'IA. La version 3.10+ a été utilisée.

\subsubsection{Flask}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/flask.png}
    \caption{Flask}
\end{figure}

Flask est un micro-framework web Python léger et flexible. Il a été utilisé pour créer le serveur API REST du backend. Sa simplicité de configuration et sa compatibilité avec les bibliothèques Python en font un choix adapté à ce projet.

\subsubsection{Groq API — Llama 3.3-70b}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/groq.png}
    \caption{Groq API}
\end{figure}

Groq est une plateforme d'inférence IA ultra-rapide utilisant des puces LPU (\textit{Language Processing Unit}) spécialisées. Elle héberge le modèle \textbf{Llama 3.3-70b} de Meta, un LLM open source de 70 milliards de paramètres. Ce modèle est utilisé pour analyser les diagrammes UML et générer le code source correspondant en Python ou PHP.

\subsubsection{PyMuPDF}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.12\textwidth]{tools/python.png}
    \caption{PyMuPDF}
\end{figure}

PyMuPDF (aussi connu sous le nom \texttt{fitz}) est une bibliothèque Python pour le traitement de fichiers PDF. Elle a été utilisée pour convertir les fichiers PDF uploadés en images, permettant ensuite leur analyse visuelle par le modèle Groq.

\subsection{Parser XMI}

Le parser XMI analyse les fichiers XMI exportés depuis StarUML. Voici un exemple de fichier XMI d'entrée et le code Python généré correspondant :

\begin{lstlisting}[language=XML, caption=Exemple de fichier XMI d'entrée]
<packagedElement xmi:type="uml:Class" name="Etudiant">
  <ownedAttribute name="nom" visibility="private">
    <type xmi:type="uml:PrimitiveType" href="String"/>
  </ownedAttribute>
  <ownedOperation name="getNom" visibility="public"/>
</packagedElement>
\end{lstlisting}

\subsection{Génération de Code Python}

\begin{lstlisting}[language=Python, caption=Exemple de code Python généré]
class Etudiant:
    """Etudiant class"""
    def __init__(self):
        self.__nom = ""

    def get_nom(self):
        return self.__nom

    def set_nom(self, nom):
        self.__nom = nom
\end{lstlisting}

\subsection{Génération de Code PHP}

\begin{lstlisting}[language=PHP, caption=Exemple de code PHP généré]
<?php
class Etudiant {
    private $nom;

    public function __construct() {
        $this->nom = "";
    }

    public function getNom() {
        return $this->nom;
    }

    public function setNom($nom) {
        $this->nom = $nom;
    }
}
?>
\end{lstlisting}

\subsection{Génération du Serveur Flask}

\begin{lstlisting}[language=Python, caption=Exemple de serveur Flask généré]
from flask import Flask, jsonify, request
app = Flask(__name__)
etudiant_store = []

@app.route('/etudiants', methods=['GET'])
def get_etudiants():
    return jsonify(etudiant_store)

@app.route('/etudiants', methods=['POST'])
def create_etudiant():
    data = request.json
    etudiant_store.append(data)
    return jsonify(data), 201

if __name__ == '__main__':
    app.run(debug=True)
\end{lstlisting}

L'interface utilisateur est développée en \textbf{React.js} avec le bundler \textbf{Vite}. L'application est organisée autour du composant principal \texttt{App.jsx} :

\subsection{Communication avec le backend}

Le frontend communique avec l'API Flask via \textbf{axios}. L'URL de l'API est définie par la variable \texttt{VITE\_API\_URL} (Vercel) ou détectée automatiquement en production (\texttt{uml-to-code.onrender.com}). En développement local, l'URL par défaut est \texttt{http://localhost:5000}.

\subsection{Adaptation mobile}

Sur écran de largeur inférieure à 768\,px, l'éditeur Monaco est masqué après génération. L'utilisateur dispose uniquement des boutons \textit{Copier}, \textit{Télécharger ZIP} et \textit{Télécharger fichier}, placés directement sous le bouton \og Générer le code \fg{}, afin d'éviter le défilement vers une zone de résultats hors écran.

\section*{Conclusion}
\addcontentsline{toc}{section}{Conclusion}

Dans ce troisième chapitre, nous avons présenté la phase de réalisation du projet UML-to-Code. Nous avons décrit l'environnement de développement, les outils techniques utilisés, les détails d'implémentation du backend Flask et du frontend React, ainsi que le déploiement de l'application sur Vercel et Render. Les tests fonctionnels et de performance ont confirmé que l'application répond aux critères d'acceptation définis dans le cahier des charges, avec un taux de succès supérieur à 95\% et des temps de génération bien inférieurs à l'objectif de 15 secondes.
